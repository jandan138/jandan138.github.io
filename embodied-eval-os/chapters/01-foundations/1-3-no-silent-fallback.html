No silent fallback：缺证据就是 blocked

上一节防的是"把窄结论说成宽结论"。这一节防的是更阴险的一种：当某个测量根本没拿到时，代码偷偷塞一个默认值替你"圆场"——返回 0.0、空列表、success=true。这种"静默回退"会把缺失伪装成结果，是证据的头号污染源。EOS 的对策斩钉截铁：缺证据，就显式记成 blocked，绝不填 0。

静默回退：把"没测到"伪装成"测到了"

想象一段再自然不过的防御式代码：某个力向量没取到，于是 force = data.get("contact_force", 0.0)；某个评估器没跑成，于是 return {"success": True} 让流水线别中断。它们看起来很"健壮"——程序不会崩。但代价是灾难性的：一个缺失的测量，被悄悄换成了一个看起来正常的数字，然后这个数字流进报告、参与聚合、被当作证据。读到报告的人无从知道这个 0 是"真的测到了 0"还是"根本没测到"。

EOS 把这类行为统称为 silent fallback，并把它列为绝对禁止。它列出了一串绝不允许出现的"默认圆场值"：

No Silent Fallback Policy — 禁止的回退
缺测量时，绝不偷偷变成：
  0.0        []        {}
  success=true          score=1.0
  default pass          隐式实跑（silently running for real）

缺证据要变成一个显式状态

取代静默回退的，是一组显式的缺失状态——它们诚实地说"这里没有证据，以及为什么没有"：

显式缺失状态（择要）
blocked_missing_measurement     blocked_missing_state
blocked_missing_artifact        blocked_invalid_action
blocked_control_rejected        blocked_provider_unavailable
blocked_optional_dependency     unsupported     not_evaluated

区别非常实在：0.0 会被下游当成一个真实读数参与平均，而 blocked_missing_measurement 不会——它从分子里退出，只在"有多少轴被 block"的计数里留痕。每一种 blocked_* 还携带了原因：是动作非法（blocked_invalid_action）、是 control 拒了（blocked_control_rejected）、还是某个 provider 根本没起来（blocked_provider_unavailable）。这样一来，"没测到"不再是一个谎，而是一条可追查的线索。下面这个部件让你左右对照同一个缺测量场景，看"填 0" 与 "标 blocked" 在报告里造成的完全不同的后果。

interactiveno silent fallback：填 0/success=true vs 显式 blocked_*
切换"静默回退"与"显式 blocked"两种处理。看同一个缺测量如何在前者里污染分数、在后者里被诚实地从分母外计数。这正是为什么 EOS 的报告永远带分母。

报告带分母与逐轴状态

显式状态只有配上分母才有意义。EOS 的报告从不只给一个"成功率 0.8"，而是要给出这个 0.8 是多少次里的、其余的为什么不算数。所以报告里带的是一组比率与计数，而不是孤零零的标量：

报告里的逐轴状态（择要）
runtime_execution_rate        model_action_valid_rate
control_acceptance_rate       projection_ready_rate
evaluator_pass_rate           render_capture_rate
artifact_linkage_failures     blocked_* counts

读这种报告的方式变了：你不是看一个数好不好看，而是看分母完不完整。如果 projection_ready_rate 只有 0.4，那么哪怕 evaluator_pass_rate 看着是 1.0，你也知道那是在一小撮"投影成功了的"样本上算的——大半样本根本没进入评估。这套纪律由 scripts/check_architecture_debt.py 与 scripts/check_required_live_lanes.py 在 CI 里强制执行：缺了该有的 lane、或者出现了可疑的"满分无分母"，就会被拦下。

从评测科学 看 一个缺失的测量，不是一个零

这在测量理论里是常识级的区分：missing data 不等于 zero。把"未观测"当作"观测到了 0"，是统计学里典型的错误——它会让你的均值、你的方差、你的结论全部失真，因为你把"我不知道"伪造成了"我知道，而且是 0"。一个没测到的接触力，既不是 0 牛，也不是任何值；它是一个空集，必须以"缺失"的身份参与（或不参与）后续计算。EOS 的 blocked_* 状态，本质就是把"缺失"作为一等公民编码进 trace，而不是让它在某个 .get(key, 0.0) 里被悄悄抹成一个数。把缺失当零，是在给自己的证据注水。

几个真实的落地点

这条纪律不是口号，它在仓库里有很多咬合点。Path B 的 live model loop（6.3）一旦拿不到 pre/post 的状态投影，就走 _finalize_blocked_loop()，把原因记进 blocking_reasons，不给这个 episode 编一个假的成功。科学实验室 pack 里，缺一个力向量被明确定义为 blocker / coverage limit，"不是 false negative，不许填 0"。判定词汇里也专门留了 blocked_with_evidence 这一档，让"被挡住但有据可查"区别于"判为不匹配"。

最常见的伪装

最危险的静默回退往往穿着"健壮性"的外衣：try/except 里默默吞掉异常返回默认值、dict.get(k, 0.0)、为了让 pipeline 不中断而 return success=True。它们不会让你的代码崩——它们让你的证据崩。在 EOS 里，宁可让流水线在这一轴上显式 blocked、报告少一格，也绝不用一个编造的数把缺口糊上。

这一节的边界声明

No silent fallback 能保证：报告里出现的每个数字都是真的测到的，缺失被显式编码为 blocked_* 并带原因与分母，从而无处藏身。它不能保证：被记录下来的那些 blocked_* 会减少——一条诚实但满是 blocker 的 trace，仍然是一条覆盖很差的 trace。这条纪律消灭的是"假装有证据"，而不是"缺证据"本身；它让你的报告变诚实，不会让它变好看。一个写满 blocked 的报告，是一个诚实地承认"我还测不到"的报告。

这一节带走的

记住这条非黑即白的纪律：缺测量时，绝不偷偷返回 0.0 / [] / success=true / 默认通过；必须变成显式的 blocked_missing_measurement / blocked_control_rejected / unsupported / not_evaluated 等状态，并带上原因。报告永远带分母与逐轴状态（execution/action_valid/control_acceptance/projection_ready/evaluator_pass/render_capture rate 与 blocked_* counts），由 check_architecture_debt.py 等脚本强制。评测科学的一句话作底：一个缺失的测量不是一个零。

这一节和上一节合起来，是 EOS 对"证据诚实"的两面防守。下一节，我们转向另一条铁律——空间上的诚实：不污染 core，把领域语义与外来概念关在它们该待的地方。
