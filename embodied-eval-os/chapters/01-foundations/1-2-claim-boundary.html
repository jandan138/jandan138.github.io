Claim boundary：永不过度宣称

上一节说证据是产品。这一节讲守护证据的那道纪律——claim boundary，EOS 的签名动作。它的形式简单到近乎刻板：每当你做出一个评测结论，都要附上一句"X 不是 Y"，明说这一步证明了什么、更要紧的是还不能证明什么。这套"主动声明非目标"的纪律，是 EOS 抵御过度宣称的免疫系统。

一个签名动作：说清边界

过度宣称（overclaiming）是评测领域最隐蔽的失败：它不报错、不崩溃，只是悄悄地把一个窄结论说成一个宽结论。"我们在仿真里检测到了危险动作"被说成"我们保证了安全"；"我们调用 AutoBio 的 SDK 跑通了"被说成"我们复现了 AutoBio"。每一步都只夸大了一点点，累积起来就是一个站不住的产品。

EOS 的对策是把"说清边界"做成一个必填动作：任何非平凡的结论，都要显式写下它的 claim boundary。这本书里你反复看到的琥珀色方框，就是这个动作的可视化。它的句式永远是"X 能证明 A，但不能证明 B"。

四个经典的"X 不是 Y"

EOS 的设计文档把最容易被混淆的几对概念钉成了固定句式，每一对都值得背下来：

docs/design/core-boundaries.md（铁律五）
semantic proxy            ≠  real CFD
compatibility smoke       ≠  full benchmark reproduction
simulator-only hazard     ≠  real-world safety certification
EBench score              ≠  scientific-lab capability
  • semantic proxy ≠ real CFD：一个 reduced 的"语义液体模型"能让你评测"移液协议步骤对不对"，但它不是计算流体力学，不能声称流体保真。
  • compatibility smoke ≠ full benchmark reproduction：跑通一次"兼容性冒烟"证明接口对得上，不证明你复现了原 benchmark 的完整结果。
  • simulator-only hazard ≠ real-world safety certification：仿真里检测到危险，不是真实世界的安全认证。
  • EBench score ≠ scientific-lab capability：在 EBench 兼容任务上拿到的分，不等于科学实验室能力。
为什么非要把"不是什么"写出来

因为沉默会被默认成宣称。如果你只报"危险检测率 0.9"而不说"这是 simulator-only hazard，不构成真实世界安全认证"，读者会自然地把它读成后者。不写边界，等于默许了最宽的解读。所以 EOS 把非目标做成必填项——claim boundary 不是谦虚，是精确。

Forbidden Claim Catalog：被点名的危险词

光靠自觉不够，EOS 还维护一张Forbidden Claim Catalog（reporting-and-claim-boundary.md §8）——一组在没有配套证据时禁止使用的词。它们之所以危险，正因为它们听起来很专业、很有分量，却最容易被空口说出：

docs/design/reporting-and-claim-boundary.md §8（节选）
MetaSim integration / compatibility      universal simulator handler
universal robot state                    TensorState-compatible EOS
backend / trajectory / contact / force-vector parity
visual or pixel parity                   OpenVLA / LeRobot success
LIBERO / ManiSkill reproduction          RoboVerse compatibility
pickup solved                            task success
official benchmark reproduction          all-backend coverage
hardware readiness                       real-world safety
parallel speedup without measured resource evidence

这张表的用法是：在写报告、写记录、写 PR 描述时，如果你用了表里的词，就必须当场拿出对应的证据；拿不出，就换一个更窄、更诚实的说法。它由 6.3 里那条 EVL lane 的 forbidden-claim checker 自动巡逻——live model loop 产出的 report 会带一组 claim_flags（backend_parity / pickup_task_success / official_benchmark_reproduction / hardware_readiness / real_world_safety / model_superiority / metasim_compatibility），默认全为 False，只有拿出证据才允许翻成 True。

Release claim levels：由窄到宽，不许跳级

claim boundary 还有一个时间维度的版本：一个能力从"刚实现"到"可以对外宣称"，要爬一道阶梯，每一级都比上一级宣称得更宽，而且不许跳级。这道阶梯（release-claim-boundary.md）是：

docs/design/release-claim-boundary.md
contract implemented
  → fixture conformance passed
    → live SDK lane executed
      → scenario evaluator executed
        → suite diagnostic executed
          → release live gate passed

关键纪律藏在文档那句话里："a live SDK lane is not a benchmark score, and a scenario evaluator result is not backend parity." 也就是说，你跑通了一条 live SDK lane（第三级），并不能直接宣称你有了 benchmark 分数（那要爬到 suite diagnostic）；你跑出了一个 scenario evaluator 结果（第四级），也不能宣称 backend parity（那根本不在这道阶梯上，是被禁的非目标）。每爬一级，都要顺手声明这一级仍然不能说的那些 non-claims。下面这个部件让你亲手在这道阶梯上爬，看看每一级"解锁了什么、仍锁着什么"。

interactiveclaim ladder：每爬一级，能宣称什么 / 仍不能宣称什么
逐级点亮这道阶梯（contract → fixture → live SDK → evaluator → suite → release gate）。注意每一级右侧"仍不能宣称"的清单——跳级，或把低一级的成果说成高一级的结论，就是过度宣称。
从评测科学 看 这就是 construct validity 与 operationalization gap

"X 不是 Y"的纪律，在评测科学里有一个正式名字：construct validity。Jacobs & Wallach（FAccT 2021）指出，每个指标都隐含一次operationalization——把一个抽象构念（"安全""能力"）翻译成一个可测的量；而这个翻译几乎总有缝隙（operationalization gap）。"simulator-only hazard 检测率"操作化的是"在某个仿真里某类危险被标出的比例"，它与"真实世界安全"这个构念之间隔着一条又宽又深的缝。Raji 等人（NeurIPS 2021）在 "AI and the Everything in the Whole Wide World Benchmark" 里进一步警告：一个号称测"通用能力"的 benchmark，往往测不出它宣称的那个普适构念。EOS 的 claim boundary，就是把这条"缝"显式写在每个结论旁边，逼自己别假装缝不存在。

这一节的边界声明

claim boundary 这套纪律能做到的，是让 EOS 的每个结论都自带"适用范围"标签，从而把过度宣称变成一个显式、可审查的违规（被 Forbidden Claim Catalog 与 claim_flags 抓住）。它不能做到的，是替你把窄结论变宽——声明边界不会增加证据，它只是禁止你假装证据更多。换句话说，claim boundary 是一面诚实的镜子，不是一台放大镜。

这一节带走的

三件事：（1）claim boundary 是 EOS 的签名动作——每个结论必带一句"X 不是 Y"，把非目标写成必填项，因为沉默会被默认成最宽的宣称；（2）四对经典对照（semantic proxy≠CFD、compatibility smoke≠full reproduction、simulator-only hazard≠real-world safety、EBench score≠scientific-lab capability）与一张 Forbidden Claim Catalog 给纪律装上了牙齿；（3）能力对外宣称要沿 release claim levels 由窄到宽逐级爬，不许跳级。这一切的评测科学根，是 construct validity 与 operationalization gap。
