怎么读这本书 · 三座桥

这本书有一个隐含的前提：你不是一张白纸。你刚走出 EBench 教程的前五章，脑子里装着 VLA、仿真栈、benchmark 方法论、client–server 评测引擎。这本书不会重教这些——它要做的，是从你已有的"家"出发，反复架桥过去。这一节交代三件事：我假设你已经会什么、那三座反复出现的"桥"长什么样、以及全书的排版与运行约定。花五分钟读它，后面会顺很多。

假设你从哪里来

我假设你读完了 EBench 教程的前五章。具体说，我假设你已经懂：VLA（一个 VLM backbone 接上输出 robot action 的能力，乃至 action chunking、flow matching、rectified flow 这些表达连续多模态动作的机制）；仿真栈（Isaac Sim = USD + PhysX + RTX，外加 cuRobo、GenManip、LeRobot）；benchmark 方法论（把单一 success rate 摊成多轴 capability profile，用 tracks × splits 守训练/测试隔离，tasks/scoring/generalization）；以及为什么评测引擎要做成 client–server。

这些不会被重讲。它们是你的出发点，是我每次引入新概念时会回头指的"你已经知道的那个东西"。如果某段读着吃力，多半是因为它默认了上面某块知识——回 EBench 教程对应章节补一下，比硬啃这里更高效。

三座桥：从已知到未知

全书每当要引入一个 EOS 的新概念，我会尽量用一座桥把它接到你已有的知识上。桥有三种颜色，各自从一个不同的"已知世界"出发。下面我把三座桥各实地展示一次——这一段里你看到的方框，就是它们后面会反复出现的样子。

桥一 · 从 EBench 看

第一座桥从你最熟的地方出发：你刚学完的 EBench。它负责把 EOS 的抽象拉回到具体的 GenManip / Lift2 / Isaac 经验上。

从 EBench 看 一座 eb 桥长这样

举个例子：当后面讲到 EOS 的 EmbodimentSpec 时，eb 桥会说——"还记得 EBench 里焊死的 Lift2 本体吗？在 EOS 里它不再是核心假设，而是众多 EmbodimentSpec 中的一个；那套 action 维度、camera 名字也一并降级，关进 adapters/ebench/。" 看到蓝色的 eb 桥，就知道："哦，这是在拿我学过的 EBench 概念作锚点。"

桥二 · 从评测科学 看

第二座桥从评测科学出发——construct validity、reproducibility、model cards 这些方法论传统。EOS 的很多"看起来很轴"的纪律，其实在评测科学里有几十年的根。

从评测科学 看 一座 ev 桥长这样

举个例子：当后面讲到"为什么不能只报一个标量分数"时，ev 桥会援引 construct validity（Jacobs & Wallach, FAccT 2021）的 operationalization gap，或 Raji 等人（NeurIPS 2021）对"Everything in the Whole Wide World Benchmark"的批评。看到绿色的 ev 桥，就知道："这条纪律不是 EOS 拍脑袋，而是评测科学早有定论。"

桥三 · 从物理后端 看

第三座桥从真实的物理引擎 / 仿真出发，提醒你 sim 不是真相、不同引擎也未必互相一致。它负责给抽象设计补上"物理现实"的重量。

从物理后端 看 一座 sm 桥长这样

举个例子：当后面讲到"为什么跨引擎结果会不一致"时，sm 桥会指出——接触是 non-smooth complementarity problem，各引擎为了速度与稳定各自松弛（线性化摩擦锥、软化互补、容忍穿透），所以同一个任务在 MuJoCo / Bullet / Genesis 上结果天然不同（参见 SimBenchmark 那类 sim2sim 研究）。看到橙色的 sm 桥，就知道："这里在提醒我别把仿真当真值。"

排版约定：读懂这些标记

正文里有几种视觉标记，含义是固定的，认熟了能加速阅读：

  • 术语高亮：像 EpisodeTrace、PhysicalStateProjection 这样的英文术语 / 类名 / 命令名，我一律保留英文并高亮——这符合论文阅读习惯，也方便你回去 grep 真实代码。中文的强调则用 这种。
  • 代码块：带文件名标头，引的都是仓库里真实的路径与类名，不是杜撰。
  • 三类 callout：.callout note 是提示，.callout warn 是坑或过度宣称的反面教材，而最重要的 .callout claim（琥珀色）是 EOS 的签名组件——凡是讲"这一步证明了什么、还不能证明什么"，都会用它。
  • verdict chip：在对比判定里你会看到这样的小标签——matched / mismatched / blocked / neutral。它们是 EOS 判定词汇的可视化，7.3 会讲清每个词的精确含义。
一条贯穿全书的标注纪律：vision vs ground truth

EOS 的文档里既有宏大的愿景（五条能力轴、五个 scenario pack、世界模型评测），也有此刻代码里真实跑得起来的地面真相（一个 SemanticProxyBackend smoke、几个 live provider、一条视觉评测 lane）。这本书会始终把两者分开标注：讲愿景时明说"这是路线图 / roadmap"，讲机制时引真实的文件名与类名。当你读到一个很厉害的说法，先问一句"这是 vision 还是 ground truth"——这正是 EOS 自己最在乎的纪律 claim boundary，我们在 1.2 会把它讲透。

怎么把这本书跑起来

这是一本交互式 HTML 教程，最好在本地起一个静态服务器来读（直接双击 file:// 打开会让搜索和部件失效）：

learn/ 目录下
cd learn
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/index.html

几个顺手的操作：按 / 唤出全文搜索（小节标题与术语都进了索引，↑↓ 选择、Enter 跳转、Esc 关闭）；右上角的 ☾ / ☀ 切换深浅色主题；每节右栏有 "On this page" 目录与 scroll-spy，左栏的章节树和上下页都由 content.js 自动生成——所以你会看到正文里我从不手写"下一页"链接。穿插的 interactive 部件可以直接上手玩，每个部件全书只出现一次，出现时我会说明"玩什么、看什么"。

这一节带走的

你已经认识了这本书的三件随身工具：（1）它默认你读完了 EBench 前五章，从那个"家"出发；（2）三座桥——eb（从 EBench 看）、ev（从评测科学 看）、sm（从物理后端 看）——会反复把新概念接回你的已知；（3）排版约定里，琥珀色的 claim 框最该盯紧，它和"vision vs ground truth"的标注纪律，是全书的脊梁。
