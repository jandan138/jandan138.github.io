写一个最小 scenario pack + model adapter

上一节你跑通了别人写好的 smoke。这一节反过来——你要往 EOS 里塞东西：一个属于你的模型、一个属于你的场景。关键不是写得多，而是写在哪一层。EOS 的全部设计都在防一件事：让你的领域语义偷偷爬进 core。所以这一节真正的功夫，是学会"最小且不越界"地扩展——不碰一行 core/，就让 runner 跑起你的世界。

三道接缝

扩展 EOS 几乎总是落在三道接缝上，对应评测路径 A 里三个可替换的零件：

  • 一个 ModelAdapter——你要评测的策略/世界模型/规划器，怎么把 observation 变成 action。
  • 一个最小 scenario——你的世界有什么语义、怎么从物理投影里读出"进展"。它不是一个 core 类，而是 pack 里的几个自由函数 + 几个 primitive 子类。
  • 一个 evaluator 判据——怎么从 trace 判定成功/进展，落进哪个 metric family。

三道接缝的共同纪律是同一句话：不改 core 抽象。core 不知道你的场景字段叫什么，它只存 schema-validated 的 payload。下面逐一看。

最小 ModelAdapter

模型契约在 model_adapters/base.py 的 ModelAdapter ABC 里。它故意只把 act() 设为 @abstractmethod，其余（reset / predict_future / rank_plans / assess_safety）都有默认实现——因为不同 model family（actor_policy / vla / world_model / planner / safety_critic …）只需实现自己那几个动词。一个最小的 actor 只要实现 reset 和 act，形状跟 8.1 用过的 RandomPolicyAdapter 一模一样：

model_adapters/my_threshold_policy.py（示意）
from embodied_eval_os.model_adapters.base import ModelAdapter


class MyThresholdPolicy(ModelAdapter):
    model_id = "my_threshold_policy"

    def __init__(self, gain: float = 0.3) -> None:
        self.gain = gain

    def reset(self, task_context: dict) -> None:
        # 只看脱敏后的 task_context；不要在这里偷看 privileged state
        self._steps = 0

    def act(self, observation: dict) -> dict[str, float]:
        self._steps += 1
        return {"delta": self.gain}

真实模型走的是同一道接缝，只是 act() 里换成对一个 sidecar model server 的 HTTP 调用——这正是仓库里已有的 HTTPPolicyAdapter（http_policy.py）做的事，它是接真模型的标准路径。model_id 会被 runner 抄进 trace 的 model_profile_id，成为 provenance 的一部分。

坑：别在 act() 里偷看特权状态

act() 只该消费脱敏后的 observation。privileged state（native dump、solver diagnostics、evaluator 真值）默认就不该进模型输入——这是 privileged_state_policy 的默认姿态。如果你的模型确实需要特权状态（state-conditioned benchmark），必须显式标注，而不是默默读进来。一旦默默读了，你的 standard_model_score 就不再合法（它默认就是 null，只有在 standard_eval + 无 privileged state + forbidden-claim 检查通过时才非空）。

最小 scenario：三个 primitive ABC + 一个 builder

这是最容易写错"层"的地方，所以慢一点。仓库里没有抽象 ScenarioPack 基类——一个 pack 不是靠继承某个大类，而是靠三件事拼出来的：

  1. 按需 subclass core/primitives 里的三个 ABC 之一——InteractionPrimitive / ProcessPrimitive / DevicePrimitive，它们各有一个 update(physical_state) -> dict；
  2. 消费 PhysicalStateProjection（backend-normalized 的物理投影，L4）；
  3. 产出一个落进 TaskSemanticState 的 dict，再加几个自由函数（builder + evaluator predicate）。

现有的 scenario_packs/visual_manipulation_micro/ 就是范本：它有一个 build_visual_push_slide_scenario(...) 返回一个 schema 打了标签的 dict，和一个 evaluate_progress(...) 判进展。照这个形状，你的最小 process primitive 可以是：

scenario_packs/my_micro/primitives.py（示意）
from embodied_eval_os.core.primitives import ProcessPrimitive


class MySlideProgressPrimitive(ProcessPrimitive):
    # 全部标清楚：这是语义代理，不是真物理，模型看不到
    fidelity_tier = "semantic_process_proxy"
    model_visible = False
    privileged_state_label = "evaluator_only"

    def update(self, physical_state) -> dict:
        obj = physical_state.objects.get("obj", {})
        pos = obj.get("pose", [0.0])[0]
        return {"slide_progress": float(pos)}

再配一个 builder，返回一个 schema-tagged 的世界声明（像 build_visual_push_slide_scenario 那样）：

scenario_packs/my_micro/scenario.py（示意）
def build_my_slide_scenario(variant_id: str = "center_goal") -> dict:
    return {
        "schema": "embodied_eval_os.scenario.my_micro.v0",
        "variant_id": variant_id,
        "allowed_backend_profiles": ["dummy_backend"],
        "privileged_state_policy": "evaluator_only",
        "official_benchmark_reproduction": False,
        "limitations": ["semantic proxy only; no contact-force evidence"],
    }

注意 dict 里那几个字段——它们不是装饰，是 契约要求里逐条对应的诚实声明，下面单独拎出来强调。

从 EBench 看 "接入自己的模型" vs "接入自己的场景"

在 EBench 里，接入你自己的模型，是写一个 ModelClient，按 client–server 协议回 action——一道接缝。EOS 把这件事拆成了两道独立接缝：模型是一个 ModelAdapter（这一节左半），场景是一个 pack（右半）。两者通过 PhysicalStateProjection / TaskSemanticState 解耦，谁都不知道对方的内部。所以你可以换模型不动场景、换场景不动模型——这正是 EBench 那套焊死的栈做不到的事。

五条不可商量的纪律

无论你的 pack 多小，下面五条都得满足。它们不是繁文缛节，而是让你的扩展"对自己诚实"的最低标准：

  • NO core changes。你的领域名（任何场景专属概念）一个都不能进 core/。core 是场景中立的契约，你的语义留在 pack。8.3 的 check_core_leakage.py 会替你把关。
  • 声明 allowed_backend_profiles。你的场景只在哪些 backend profile 上有意义，写明白。别让别人拿一个语义代理 profile 去声称物理结论。
  • privileged_state_policy = evaluator_only。过程/危险/真值字段是 evaluator 看的，不是模型输入。
  • 至少留一条 smoke / dummy 路径。哪怕只能在 dummy_backend 上跑通一条 trace，也比"声称支持却跑不起来"强。可跑通 = 可审计。
  • 写清 limitations 与 official_benchmark_reproduction = false。语义代理就老实说是语义代理。一个 semantic proxy primitive 不得声称与任何官方 benchmark 插件物理等价。

第三道接缝——evaluator——同样小。你只需要一个判据函数（或一个 Evaluator 子类的 evaluate_episode(trace)），把 slide_progress 这样的语义字段折成一个 MetricResult，归到某个抽象 family（如 task_outcome 或 procedure）。family 是 core 定义的抽象，metric 实例由你的 pack 给出——这条分工我们在 5.1 讲过。别在 family 名里塞领域词。

一个最小 pack 证明了什么 / 不证明什么

证明：你的场景语义能被 EOS 的层表达（primitive → TaskSemanticState）、能跑出一条合法 trace、能被一个 evaluator 判读——而且没动 core。
不证明：你的语义代理在物理上正确，或与任何官方 benchmark 等价。fidelity_tier="semantic_process_proxy" 和 official_benchmark_reproduction=false 这两个标签，就是你在 trace 里替自己划下的诚实边界。"我能用 EOS 的层表达 AutoBio 风格的任务"不等于"我复现了 AutoBio 的物理"——这正是 records 里 faithful_reproduction_not_approved 那场清算的教训。

这一节带走的

扩展 EOS 的全部技巧，可以压成一句话：把你的领域语义放进 pack，把你的模型放进 adapter，让 core 一个字都不知道。三道接缝（model adapter / scenario primitive + builder / evaluator predicate）都很小，难的不是写，而是写在对的层、并在 dict 里把 allowed_backend_profiles、privileged_state_policy、limitations、official_benchmark_reproduction 这些诚实标签填齐。

但"我没动 core"这句话不能光靠自觉。下一节，我们看 EOS 用什么样的 PR 纪律——必跑命令、make gate、Record Rule、claim boundary 模板——把这份自觉变成项目级的、自动执行的诚实。
