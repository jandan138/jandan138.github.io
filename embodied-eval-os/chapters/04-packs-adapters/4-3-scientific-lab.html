scientific_lab：把禁词关进笼子

还记得那张禁词表吗——Pipette、TubeRack、Contamination，一旦出现在 core/ 里就让 CI 失败。但 EOS 偏偏要做一个科学实验室评测。这些词总得有地方住。这一节看 EOS 的旗舰 pack scientific_lab：它正是那个"笼子"——禁词在这里合法地存在，被关进一个 core 看不见的角落，既表达了领域语义，又不污染契约骨架。

三层任务层级

scientific_lab 不是一堆零散任务的集合，它有清晰的能力层级，从最原子的物理动作往上长：

scientific_lab 任务层级
atomic physical abilities      # 原子物理能力：抓、放、对准
   ↓
scientific operation skills    # 科学操作技能：拧盖、移液
   ↓
long-horizon scientific tasks  # 长程科学任务：完整实验流程

前三个任务很具体：pick/place 一支离心管、拧开管盖、移液（aspiration/dispense）的 proxy。这条层级和 五条能力轴里的 task execution / generalization 直接对应——越往上越考验长程规划与跨场景泛化。

proxy 原语：全是 semantic，全对模型不可见

pack 的核心是一组语义代理原语（proxy primitives），它们就是 4.1 讲的"subclass 三个 ABC"的真身：PipetteProxyPrimitive、ThreadedCapProxyPrimitive、LiquidVolumeProxyPrimitive、RackSlotPrimitive、InstrumentStatePrimitive……名字里全是禁词，但它们住在 scenario_packs/scientific_lab/process_primitives/，core 永远碰不到。

去读 process_primitives/pipette_process.py，你会看到这些原语有两个不可省的标记：

scenario_packs/scientific_lab/process_primitives/pipette_process.py
FIDELITY_TIER = "semantic_process_proxy"

class PipetteLiquidMaterialPrimitive(ProcessPrimitive):
    primitive_id = "scientific_lab.pipette_liquid_material_proxy"

    def update(self, physical_state: PhysicalStateProjection) -> dict[str, Any]:
        del physical_state                       # 注意：根本没用物理状态
        source_volume_ul = self.initial_volume_ul - self.aspirated_volume_ul
        return {
            "schema": "scientific_lab.pipette_liquid_material_state.v0",
            "fidelity_tier": FIDELITY_TIER,        # = semantic_process_proxy
            "source": "scenario_process_proxy",
            "volume_error_ul": float(abs(self.target_volume_ul
                                         - self.aspirated_volume_ul)),
            "evaluator_visible": True,
            "model_visible": False,                # 对被测模型不可见
            "privileged_state_label": "evaluator_only",
        }

两件事值得盯住。第一，每个 proxy 都打 fidelity_tier="semantic_process_proxy"——它在用词上就主动招认"我是语义代理，不是高保真物理"。第二，全部标 model_visible=False + privileged_state_label="evaluator_only"：这些过程状态是特权状态，只给 evaluator 看，绝不喂给被测模型。注意那行 del physical_state——这个 liquid proxy 甚至没去读物理投影，它的"体积误差"完全来自一个解析的语义模型。

从 EBench 看 这就是被关进笼子的"领域语义"

在 EBench 里，"移液成功"这种判据是和 Isaac、GenManip 焊在一起的，谁也没拦着它往评测核心里渗。EOS 把同样的语义抽出来，强制它只能以 model_visible=False 的过程 proxy 形式、住在 pack 目录里。这就是 4.1 那句"contract 不靠基类靠组合 + leakage checker"的回报：禁词得到了一个合法住所，core 保持干净。

任务投影：从物理量到语义判据

pack 还拥有一组任务投影名（projection names）——它们是 pack 从 PhysicalStateProjection 里读出、再翻成语义判据的字段。例如：

scientific_lab 任务投影（pack 拥有）
finger_cap_contact          # 手指是否接触到盖子
finger_cap_contact_force    # 该接触的力
gripper_aperture_response   # 夹爪开合响应
tube_cap_body_retention     # 盖与管体是否保持连接
thread_retention_support    # 螺纹保持支撑

这些名字 core 一个都不认识——core 只存 schema-validated 的 payload（回忆 L5 TaskSemanticState 的设计）。它们是 pack 私有的语义词汇。

三个分开的力家族：缺力是 blocker，不是 0

这是 scientific_lab 最能体现 EOS 纪律的地方。一个"盖子被保持住"的力，可能来自三个完全不同的来源，pack 把它们拆成三个独立的力家族，绝不混为一谈：

三个分开的力家族
finger_cap_contact_force       # native 接触求解器算出的接触力
retention_constraint_force     # primitive / equality / weld 等约束保持力
mujoco_thread_contact_force    # MuJoCo 源的螺纹/接触保持力

为什么非要拆？因为这三种力的证据含义不同：一个来自后端的真实接触求解，一个来自人为加的约束（weld/equality），一个来自 MuJoCo 特定的螺纹模型。把它们加在一起或互相替代，就等于在偷偷地"用约束力冒充接触力"——这会让一个"盖子拧紧了"的结论建立在错误的证据上。

更关键的纪律是：当某个力向量缺失时，它是一个 blocker / coverage limit，不是 false negative，绝不允许填 0。 这正是 No Silent Fallback 在 pack 层的体现——某个后端测不出 finger_cap_contact_force，报告里就记一个 blocked_missing_measurement，而不是悄悄写 force = 0.0 然后判定"没接触"。

填 0 是最隐蔽的谎言

"测不到力就当力是 0"看起来人畜无害，但它把一个覆盖缺口伪装成了一个物理事实（"确实没接触"）。下游评测会据此判任务失败——一个本可能成功的 episode，被一个缺失的传感器通道误杀。EOS 宁可让结果显式 blocked，也不接受这种沉默的零填充。

禁词正是在这里合法存在

把前面几节串起来：core/ 里写 core.PipettePrimitive / core.ContaminationMetric / core.TubeRackSlot 是错的（leakage checker 会拦）；而 scenario_packs/scientific_lab/process_primitives/pipette_proxy.py 里写 PipetteProxyPrimitive 是对的。同一个概念，位置决定合法性。这就是"把禁词关进笼子"的字面含义——禁词不是被消灭，而是被定位到唯一允许它存在的层。

Non-goals：它不假装是真化学

最后，pack 文档明确列了一串非目标，把 claim 边界从一开始就钉死：

scientific_lab Non-goals
NOT high-fidelity CFD
NOT real chemical reaction simulation
NOT true microfluidics
NOT real thermal fracture
NOT real-world safety certification
NOT full AutoBio faithful reproduction inside Isaac
semantic proxy ≠ real CFD

scientific_lab 的 liquid_volume_error_ul 来自一个 semantic_process_proxy 原语——一个解析的体积差，根本没跑流体求解。它证明的是移液任务的语义结构可以被表达、被评测、且过程状态作为特权信息不泄漏给模型。它不证明：真实的液体动力学、表面张力、微流控、或任何 CFD 量级的物理。"semantic liquid proxy metric" 与 "real fluid dynamics" 是两个量级的东西，报告里必须分开声明。

这一节带走的

三点：（1）scientific_lab 是旗舰 pack，任务分 atomic → skill → long-horizon 三层，proxy 原语（PipetteProxyPrimitive 等）全标 fidelity_tier=semantic_process_proxy + model_visible=False；（2）三个力家族（finger_cap_contact_force / retention_constraint_force / mujoco_thread_contact_force）必须分开，缺力是 blocked 不是 0；（3）禁词（Pipette/TubeRack/Contamination）正是在这个 pack 里合法存在——位置决定合法性，而 non-goals 把它和真 CFD/化学的边界钉死。
