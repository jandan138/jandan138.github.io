模型家族与可见性模式

前两节讲的是"测什么"和"画成什么"。这一节讲"被测的是谁"。EBench 里"模型"几乎等同于 VLA。EOS 要评的东西更杂：纯 actor、世界模型、规划器、安全评判器、自主智能体——它们实现不同的方法、扮演不同的角色、在不同的可见性模式下被测。最锋利的一条纪律是：standard_model_score 默认是 null，除非一组严格条件全部满足。

模型家族：契约不为 VLA 量身定做

EOS 把被评测对象按"它能做什么"分成若干家族。VLA 只是其中之一，而不是默认：

  • actor_policy / vla——给观测、出动作。EBench 那个 VLA 落在这里。
  • world_model（WAM）——给观测和一段动作序列，预测未来状态/观测。
  • planner——在候选计划里排序、择优。
  • safety_critic——给一个候选动作，评估它的危险性。
  • autonomous_agent——上述能力的组合体，自己跑完一整段。

这五个家族不是凭空划的——它们直接对应 ModelAdapter 契约上那几个方法。core 不假设一个模型"是 VLA"，只假设它"实现了契约里的某几个方法"。

ModelAdapter：一个契约，五种实现深度

打开 model_adapters/base.py，整个契约就这么大——一个 ABC，一个必须实现的方法，外加四个可选方法：

src/embodied_eval_os/model_adapters/base.py
class ModelAdapter(ABC):
    """Different models may implement one or more methods:
    actor policy, world predictor, planner, safety critic, autonomous agent."""
    model_id: str

    def reset(self, task_context: dict) -> None: ...

    @abstractmethod
    def act(self, observation: dict) -> dict | list[float]: ...

    def predict_future(self, observation, action_sequence) -> PredictedFuture:
        raise NotImplementedError

    def rank_plans(self, observation, candidate_plans) -> list:
        raise NotImplementedError

    def assess_safety(self, observation, candidate_action) -> dict[str, float]:
        raise NotImplementedError

方法到家族是一一对应的：act ↔ actor_policy / vla（唯一 @abstractmethod，因为最低限度你得能出动作）；predict_future ↔ world_model（返回 PredictedFuture）；rank_plans ↔ planner；assess_safety ↔ safety_critic。四个可选方法默认抛 NotImplementedError——这是有意的：一个纯 actor 不假装会预测未来，评测器据此知道哪几根能力轴对它根本不适用（落到 unsupported 状态，而不是给个假分）。

现成的实现住在 model_adapters/：random_policy.py、scripted_policy.py、以及 http_policy.py（HTTPPolicyAdapter——把真模型放进一个 sidecar 进程、用 HTTP 通信的真模型接入路径，正是 EVL lane 要替换 scripted policy 时走的口子）。

从评测科学 看 世界模型按"规划有用性"评，不按像素保真

注意 predict_future 和 rank_plans 在契约里是分开的两个方法——这呼应 5.2 的解耦轴。VP²（Tian, Finn, Wu, ICLR 2023）已证"perceptual video metrics can be unreliable at predicting execution success"：world model 不该靠 predict_future 的像素重建质量打分，而该靠它接进 rank_plans 后下游决策变好了多少。DreamerV3（Nature, 2025）同样把 world model 的价值锚在"能拿来做控制决策"。EOS 把这条认识做成了契约形状：会预测和能帮规划是两个独立方法，因此可以被独立评、独立缺失。

policy roles：同一个模型，不同的身份

家族讲的是"能做什么"，role 讲的是"在这次评测里扮演什么"。同一个 actor_policy，可以是被考的人，也可以是参照系。EOS 区分这些角色：

  • evaluated_model——真正被打分的那个（唯一能产出 standard score 的角色）。
  • reference_policy——参照基线，用来给"难易"定标。
  • oracle_policy——拿了 privileged 真值的上界参照。
  • scripted_demonstrator / human_demonstrator——脚本/人类示范源。
  • safety_supervisor——在回路里兜底安全的监督者。

角色之所以重要，是因为它直接决定一个结果"算不算 standard score"——一个 oracle_policy 跑出来的成功率再高，也不能被读成"模型能力"，因为它作弊看了真值。

三种 eval 模式与那个 null 分数

与角色正交的是 eval 模式，它声明这次评测放行了多少 privileged 信息给模型：

  • standard_eval——模型只看到脱敏后的 model-visible observation，不含 privileged state。
  • privileged_eval——刻意放行部分真值（用于诊断"如果它知道这个，会不会做对"）。
  • oracle_eval——给满真值，求能力上界。

现在是这一章最重要的一条规则。报告里那个 standard_model_score 字段，默认是 null，只有当下面每一条都成立它才允许非空：

standard_model_score 非 null 的全部前提
role  == evaluated_model
mode  == standard_eval
protocol 是正式协议（不是 smoke / 探针 / 临时跑）
该 episode 的 model 输入中没有混入 privileged state
forbidden-claim 检查全部通过（不含 model superiority / parity / … 等禁词）
缺任一前提 → standard_model_score = null（不是 0.0，不是 success=true）

这条规则把"我跑出了一个数"和"这个数可以被当成模型能力"彻底分开。一个 privileged_eval 跑出 0.9，standard_model_score 依然是 null——因为它不满足 standard 的脱敏前提。宁可留空，绝不给一个会被误读的数。

脱敏发生在哪里

"模型看不到 privileged state"不是靠君子协定，是靠代码：live model loop（6.3）里有一步 _build_model_visible_observation()，专门剥掉 privileged 字段、native state dump、solver diagnostics、evaluator 真值，再喂给 act()。每条 trace 还记一个 privileged_state_visible_to_model 标志（默认 False），让"这次到底脱没脱敏"成为可审计的证据，而非声明。

从 EBench 看 AutoBio 的 Expert，降级成通用的 ReferencePolicyProfile

AutoBio（接入在 adapter 里）带了一个叫 Expert 的 privileged scripted demonstrator——它是 benchmark 专属概念。按铁律一，Expert 不许进 core。EOS 的做法是把它在 core 里表述成一个通用的 ReferencePolicyProfile / DemonstrationSourceProfile：core 只知道"有一个参照策略/示范源，role=scripted_demonstrator，privileged"，而 "AutoBio 的 Expert" 这个具体身份留在 adapter。家族 + 角色 + 模式这套词汇，正是为了能在不认识任何具体 benchmark的前提下，准确描述每个被接入的策略到底是什么。

一个非空分数证明了什么 / 没证明什么

当 standard_model_score 真的非空时，它证明的是：一个 evaluated_model 在 standard_eval、脱敏、正式协议、禁词检查通过的条件下，取得了这个可审计的结果。它不证明这个模型"比别的模型强"（model superiority 是禁词，要还原到逐轴逐 split），更不证明"它在真实世界能用"。而当分数是 null 时——这同样是一条诚实的证据，意思是"在 standard 条件下没有可声称的分数"，而不是"测了个 0"。

这一节带走的

三点：（1）EOS 按能力把模型分成 actor_policy/vla、world_model、planner、safety_critic、autonomous_agent 五个家族，一一对应 ModelAdapter 的 act / predict_future / rank_plans / assess_safety 方法，只有 act 是必须实现的；（2）role（evaluated_model / reference / oracle / demonstrator / safety_supervisor）与 mode（standard / privileged / oracle）正交，共同决定一个结果的身份；（3）standard_model_score 默认 null，只在 evaluated_model + standard_eval + 脱敏 + 正式协议 + 禁词检查全过时才非空——AutoBio 的 Expert 也因此降级成通用的 ReferencePolicyProfile。

最后一节，我们把放大镜对准度量本身的边界：一个 semantic proxy 度量到底证明了什么，以及把多轴结果聚合时会踩到的那些统计陷阱——包括 Simpson 悖论。
