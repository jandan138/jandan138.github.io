五条能力轴与 CapabilityProfile

5.1 把度量归并到 family。这一节再上一格：把 family 汇成一份给人看的画像。EOS 沿五条能力轴给具身智能打分，并把结果组织成一个结构化的 CapabilityProfile 报告。最重要的纪律只有一句——永远不给单一总分。我们会再用一次能力雷达图，但换一个角度：去看为什么"会预测像素"和"对规划有用"是两根独立的轴。

五条能力轴，再看一遍

0.1 里你已见过这五条轴。这里我们把它当作报告的骨架重新摆一遍，因为 CapabilityProfile 就是绕着它们组织的：

  1. task execution——任务执行：做没做成（喂自 task_outcome family）。
  2. world prediction（WAM / world model）——世界预测：模型能否预言接下来会发生什么（喂自 prediction / state_transition）。
  3. safety reasoning——安全推理：预判危险、识别边界、拒绝危险动作（喂自 hazard）。
  4. generalization——泛化：换物体/场景/后端/渲染/本体还行不行。
  5. planning usefulness——规划有用性：世界模型真能帮上规划与安全决策吗（喂自 planning）。

注意第 2 和第 5 条之间那道刻意挖开的鸿沟。一个直觉很强的误解是：世界模型预测得越准，对规划当然越有用。EOS 的设计明确拒绝把这两者合并——它们是两根解耦的轴。

解耦的两根轴：预测得好 ≠ 规划有用

为什么要分开？设想一个世界模型，它对未来 RGB 帧的预测在像素层面极其逼真——桌面纹理、光影、杯子的高光全对。可当你拿它去做规划（"如果我现在伸手去抓，会不会打翻试管？"），它给出的决策相关信号——接触会不会发生、试管会不会被碰倒——却是错的。反过来也成立：一个在像素上糊成一团、但能可靠回答"这个动作安不安全"的模型，在 planning usefulness 轴上可能更高。

$$\text{world prediction score} \;\perp\; \text{planning usefulness score}$$

这两个分数在 EOS 里被设计成近似正交：world prediction 问"你预测的状态/观测离真值有多远"（state_transition / prediction family）；planning usefulness 问"把你的预测接进一个规划/决策回路后，下游的成功率或安全决策有没有变好"（planning family，例如让世界模型 rank_plans 后任务成功率的增益）。两者由不同的度量、不同的 trace 字段喂养，因此可以分别高、分别低。

interactive同一个世界模型：像素轴很高，规划轴塌陷
这次别只看"哪个模型总分高"。盯住 world prediction 和 planning usefulness 两根轴：一个 world model 可以在前者很长、在后者很短——会"画"未来，却帮不了决策。单一总分会把这道致命缝隙抹平。数值为示意。
从评测科学 看 世界模型该按"对规划有用"评，不是按像素保真

这正是 VP²（Tian, Finn, Wu, ICLR 2023）的核心发现："perceptual video metrics can be unreliable at predicting execution success"——感知层面的视频指标（PSNR、SSIM、FVD 这类像素保真度）和"这个预测能不能支撑控制成功"之间相关性很弱。DreamerV3（Nature 640:647–653, 2025）则反向印证同一点：它在极多样的控制任务上靠学到的 world model 做规划取得成功，证明 world model 的价值在"能不能拿来做决策"，而非"重建得多像"。EOS 把这条认识硬编码进了报告结构——world prediction 与 planning usefulness 是两根不能互相替代的轴。

CapabilityProfile：多轴分解，而非一个数

这五条能力轴是面向叙事的高层维度；落到具体报告类型 CapabilityProfile 时，它会被进一步细分成更多可独立读出的子维度——这样每一面都能被单独审计：

CapabilityProfile（多轴分解，示意结构）
{
  "task_outcome":         { "value": 0.61, "n": 100, "status": "exact" },
  "procedure_validity":   { "value": 0.74, "n": 100, "status": "exact" },
  "precision":            { "value": "1.8 ul", "status": "approximate" },
  "hazard_safety":        { "ddr": 0.55, "fnr_h": 0.21, "status": "exact" },
  "prediction":           { "ste": 0.12, "status": "exact" },
  "planning_usefulness":  { "value": null, "status": "blocked_missing_artifact" },
  "generalization":       { "render_split": 0.48, "physics_split": null },
  "resource_cost":        { "steps": 84, "wall_s": 31.2 }
}

三件事请你在这个结构里看出来。其一，每根轴自带分母与状态（n、status）——一个轴可以是 exact / approximate，也可以诚实地是 blocked_missing_artifact（这里 planning usefulness 因为缺规划产物而被 block，不填 0，呼应铁律三）。其二，generalization 被进一步拆成 render_split 与 physics_split——换渲染器的泛化和换物理引擎的泛化是不同的事（这道区分在 5.4 会被反复强调）。其三，没有任何一个字段叫 overall_score。

"没有单一标量"是一条规则

这不是 EOS 忘了加总分，而是它明令禁止加。把多轴塌成一个数，等于宣布"我知道这五条轴该怎么加权"——而这个权重恰恰是价值判断，不是测量结果。一个长于 task execution、却在 safety reasoning 上漏报危险的模型，和一个反过来的模型，凭什么用同一个加权和比较？任何固定权重都会偷偷把某一类失败定价为"可接受"。

这份报告证明了什么 / 没证明什么

一份 CapabilityProfile 证明的是：在它列出的每一根轴上、在它写明的分母与状态下，模型取得了这些可审计的结果。它不提供、也不许被读成一个"综合能力分"。"模型 A 比模型 B 强"这种 model superiority 论断，没有任何单一标量能支撑——它必须被还原成"在哪根轴、哪个 split、什么分母下，A 高于 B"。这正是 standard_model_score 默认为 null 的原因（见 5.3）：宁可留空，也不给一个会被误读成总分的数。

从评测科学 看 多轴画像胜过单一标量，早有先例

"别用一个数概括一个能力体系"在评测科学里是反复被验证的教训。HELM（Liang et al., 2022）把语言模型评测从"一个 leaderboard 分"重构成一张 scenarios × metrics 的多维矩阵，明确主张holistic 评测。机器人领域的 BEHAVIOR / BEHAVIOR-1K（CoRL 2022 / 2023）同样沿多个能力维度铺开长程家务任务，而非一个成功率。Dynabench（Kiela et al., NAACL 2021）则从另一面论证：静态的单一基准会被"刷分"，需要多维、动态的视角。EOS 的五条轴 + CapabilityProfile，是把这条共识搬到具身智能上的一次具体落地。

这一节带走的

三点：（1）EOS 沿五条能力轴（task execution / world prediction / safety reasoning / generalization / planning usefulness）组织一份结构化的 CapabilityProfile 报告，每根轴自带分母与状态、可被 block；（2）world prediction 与 planning usefulness 是解耦的两根轴——会预测像素不等于对规划有用，这条认识直接来自 VP² 与 DreamerV3；（3）"没有单一标量"是一条规则而非疏忽——任何总分都隐含一个不该由测量做出的价值加权。
