Live model loop：观测 → 动作 → 证据

上一节我们看了八个动词的 facade。这一节把它们串成一条完整的链——run_rpf10_live_model_loop。这条链回答的是路径 B 真正的问题：当一个真实模型在一个真实后端上做一次决策，怎样让它"看到该看的、看不到不该看的"，又怎样把这一来一回固化成谁也赖不掉的证据。它的每个环节都在跟一种"作弊"或"幻觉"较劲。

一条链，十几个环节

RPF-10 / EVL 的 live model loop 把八动词按一个固定顺序编排起来，中间插进脱敏、投影、判定与组装。整条链大致是这样：

src/embodied_eval_os/runtime/live_model_loop.py — run_rpf10_live_model_loop
materialize  → reset  → measure(pre)
   → build model-visible observation   (脱敏：去 privileged / native dump
                                        / solver diagnostics / evaluator truth)
   → policy.act(observation)
   → apply_control(action) → ack
   → step → measure(post)
   → query_evidence(telemetry / solver_diagnostics / native_state_dump)
   → build post PhysicalStateProjection → motion_delta → evaluator_result
   → close
   → assemble EpisodeTrace  → report.json (claim_flags 全 False)

注意这条链和路径 A 的 runner 形状相似（也是 reset→act→step→measure），但每一步都被"证据化"了：measure 分成 pre 与 post 两次、动作要先变成 WorldSessionControlRequest 再换回一个 ack、所有产物都是 hash 寻址的 ArtifactRef。最后这些产物被缝进一条 EpisodeTrace，每步的 task_semantic_state.procedure_state["runtime_flow"] 里记着这一拍走过的动词序列。

脱敏：让模型看不见"答案"

整条链最微妙、也最像"评测科学"的一环，是 _build_model_visible_observation。measure(pre) 抓到的快照里，可能塞满了模型不该看到的东西：privileged state（物体真实位姿、评判用的真值）、native dump（后端自己的内部状态）、solver diagnostics（求解器诊断）、evaluator truth（评判答案）。这个函数的工作，就是把这些统统挡在模型可见的观测之外，只留下一个干净的、模型在真实部署中本就能拿到的观测，并在 payload 里记下 privileged_fields_withheld 与 privileged_state_visible_to_model: False。

从评测科学 看 脱敏就是在守 construct validity

如果模型在决策时能偷看 evaluator truth 或物体真值，那你测到的就不是"它的能力"，而是"它抄答案的能力"——这是最经典的 construct validity 失效（Jacobs & Wallach, FAccT 2021）：你声称在测 A，实测的是 B。state-conditioned 的 benchmark 不是不能给模型喂特权状态，但必须显式标注，否则那个分数测的根本不是它宣称的构念。_build_model_visible_observation 这一步脱敏，就是把"防作弊"做成代码里强制的一道墙——默认模型输入不含 privileged state，例外必须显式声明。

No silent fallback：缺测量 → blocked，不是 0

这条链最硬的纪律，是它对"缺东西"的反应。假如 measure(pre) 或 measure(post) 没拿到该有的状态值，链不会假装一切正常、把 motion_delta 填成 0、把 success 填成 true。它会调用 _finalize_blocked_loop()，在 trace 与 report 里写下 blocking_reasons（比如 blocked_missing_measurement），把这一拍标成 blocked。

这件事为什么重要？因为"缺测量填 0"是评测里最隐蔽的谎言——它把"我没测到"伪装成"我测到了，结果是 0"。前者是证据缺口，后者是阴性证据，两者的含义天差地别。EOS 用一整套 blocked_* 状态把这条缝堵死：缺测量、缺状态、缺 artifact、控制被拒、provider 不可用……每一种都有自己的显式状态码，谁也不许悄悄退化成默认值。强类型的验收落在 core/runtime/episode_execution.py 的 EpisodeExecutionResult 上：task_success 只有当 EvaluatorOutcomeArtifact.accepted_for_linkage 为真时才非 None，否则它就是 None，而不是 False——"还没判"和"判为失败"也被分得清清楚楚。

报告里那排全 False 的 claim_flags

链跑完，组装出 report.json，里面有一排 claim_flags：backend_parity、pickup_task_success、official_benchmark_reproduction、hardware_readiness、real_world_safety、model_superiority、metasim_compatibility——全部为 False。这不是谦虚，是制度。这条 lane 哪怕真的让一个模型在真后端上动了起来、产出了漂亮的 trace，它默认什么大结论都不声称。同样地 standard_model_score 默认是 null，只有在评判产物被接纳挂链、且 forbidden-claim 检查通过后才可能非空。报告的姿态是"先全部否认，再凭证据逐条解禁"。

EVL-1：当前的前沿

这条 live model loop 的当前最前沿实例叫 EVL-1（Evidence-backed Visual Model Evaluation Lane）。它把上面的链具体化到视觉评测：

  • RGB 证据：观测是真实的 RGB 帧，存成 .npy 并 hash——画面本身成为 artifact-backed 的证据，而不是一个口头"我看到了图像"。
  • 真模型路径：用 stdlib 实现的 HTTPPolicyAdapter，让一个真实模型可以隔着 HTTP 接进来出动作（仅依赖标准库，不引重型框架）。
  • 微场景：跑在 visual_manipulation_micro 这个 scenario pack 上，小而完整。
  • 诊断套件：一个 10-episode 的诊断 suite，配 failure taxonomy（失败分类）与 forbidden-claim checker（禁词检查器），自动拦住报告里的过度宣称。

而被点名的下一步是 EVL-2：用一个真正的 sidecar model server 替换掉 EVL-1 里的 scripted policy——也就是从"脚本演示者驱动这条链"升级到"真模型服务驱动这条链"。注意这条演进的克制：先把链与证据机制钉死（EVL-1），再换上真模型（EVL-2），而不是反过来先接大模型、再补证据。

EVL-1 这条 lane 证明了什么 / 还不能证明什么

EVL-1 证明的是：一个模型能在一条 RGB-证据化、特权状态脱敏、缺测量即 blocked、claim_flags 默认全 False 的 live lane 上跑完一个诊断 episode，并留下可审计的 artifact。它不证明这个模型在视觉操作上有任何能力高低——一条 live lane 不是 benchmark score，model_superiority 那一栏默认就是 False。它也不证明 visual_manipulation_micro 里的"成功"等于真实世界的成功。这条 lane 的价值在于证据的质量（脱敏正确、产物可 hash、缺口不被掩盖），不在于它跑出了什么漂亮数字。

这一节带走的

RPF-10 的 live model loop 把八动词串成一条证据链：materialize→reset→measure(pre)→脱敏观测→policy.act→apply_control(ack)→step→measure(post)→query_evidence→投影→motion_delta→evaluator_result→close→组装 EpisodeTrace→report.json。脱敏（_build_model_visible_observation）守住 construct validity；no-silent-fallback 让缺 pre/post 测量变成 blocked 而非 0；report 的 claim_flags 默认全 False。当前前沿是 EVL-1（RGB 帧 hash、HTTPPolicyAdapter、visual_manipulation_micro、10-episode 诊断 + 禁词检查），下一步 EVL-2 换上真 sidecar 模型服务。

最后一节，我们退后一步看治理：fixture-driven 的 conformance kit 怎样判 provider，以及 release claim levels 这把阶梯与那一串 make gate 怎样把"调通"一级一级抬到"可发布"。
