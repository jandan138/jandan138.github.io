Judgeable loop：把分叉记成账

上一节我们能看见两个引擎在哪一步分叉了。但"看见差异"和"敢用差异下结论"之间，隔着一道很深的鸿沟。如果你都没确认两边跑的是同一个起点、同一套动作、控制真被接受、关节真有响应，那么任何"它们不一样"的判断都可能只是你自己测错了。R1 到 R15 这场取证式（forensic）的拉锯，就是去把这道鸿沟一寸寸填平。

"judgeable"是什么意思

judgeable loop 的核心洞见，是把比较拆成两层：先过 fairness gates（公平性闸门），再下 physical verdict（物理判决）。fairness gates 问的是"这场比较公不公平"，它们必须先全部通过，物理判决才被允许成立。这些闸门包括：

  • 两边是否同一个 state0 hash（起始状态逐位相同）；
  • 是否同一套 action schedule（重放同一条动作序列）；
  • 控制是否被 ack（control acknowledgement，命令真的被接受了）；
  • 关节是否真有 response（joint response，动了，不是发了指令却没动）。

只有这些闸门都绿了，"两个引擎的接触力不一样"才是一个关于物理的结论，而不是一个关于我装置没搭对的结论。物理判决本身用一套受控词汇表达：

matched mismatched blocked_with_evidence not_compared

注意 blocked_with_evidence 与 not_compared 的存在——它们让"我没法比"和"我比了、一样/不一样"被明确区分开，而不是把无法比较的东西硬塞进 matched 或 mismatched。这是 No Silent Fallback 在判决层的化身：缺证据就如实记缺证据。

从评测科学 看 这就是 construct validity 在跑

fairness gates 不是工程洁癖，它是 construct validity（Jacobs & Wallach, FAccT 2021）落到比较层的样子：你声称在测"两个引擎的物理差异"，可如果起点 hash 不同、动作没对齐、控制没被接受，你实测的其实是"我的装配误差"，而不是你声称的那个构念。Henderson 等人（"Deep RL that Matters", AAAI 2018）早就警告过：不控住 extrinsic / intrinsic 变异，RL 的对比结论会变得不可复现。judgeable loop 把"公平"做成了下结论前的硬前置——先证明比较成立，再相信比较结果。

R13：七个作动器的力律项相等

这场取证里最漂亮的一仗是 R13。控制链是否"公平"，不能只看"动作重放了"，还要看两边的力律（force law）是不是同一回事。对常见的 position actuator，单步施加的力可以写成一个仿射形式：

$$ \text{force} = \text{gain}\cdot\text{target} + \text{bias}_0 + \text{bias}_1\cdot q_{pos} + \text{bias}_2\cdot q_{vel} $$

R13 做的事，是对 7 个公共 actuator 逐项比对这些系数（gain、三个 bias 项），结果是每一项的 delta 都是 0.0：

R13 → R15 report 摘录
control_force_term_delta_max          = 0.0
common_actuator_force_term_matched_count = 7

这是一个极强、极窄的 verdict：控制链在力律项级别上 matched。它不说轨迹一样，不说接触力一样——它只说"喂给两个引擎的力，是按同一条公式、同样系数算出来的"。这种把比较切到最细的可证粒度，正是 judgeable loop 的精髓：把一个模糊的"控制公平吗"，拆成一个可以打 0.0 的具体账目。

R15：把未知 blocker 变成已声明的 non-equivalence

到 R14 时，账面上还挂着几个"blocker"——它们被列为未知的拦路项，比如手指接触力的 norm 不匹配、力向量基底未对齐、source 侧的 qacc_warmstart 在 Genesis 侧无对应物。R15 问了一个收尾问题：这些到底是未知的坑，还是有证据支撑、可以显式带着走的 non-equivalence？

R15 的判决是后者。它把每一条剩余差异都归类为"accounted"（已记账），最终关闭为：

读一遍这张表就懂了它的美学：机器人关节响应是一个被测到的轨迹 mismatch（first divergence 在第 7 步，max abs delta ≈ 0.073）；控制链是 matched 的力律项；手指接触力在 norm 层 mismatch、向量基底 not_equated；qacc_warmstart 因 Genesis 侧无绑定，被声明为一个 declared non-equivalence。关键在 unaccounted_blocking_reasons=[]——每一处剩余的不一致，都从"未知 blocker"变成了"有证据背书、显式声明的 non-equivalence"。没有一个差异是悄悄藏起来的，也没有一个是含糊不清的。

R15 关闭了什么、绝不声称什么

R15 关闭的是账本，不是 parity。它证明：在公平闸门全绿的前提下，两个引擎的每一处差异都已被归类、被证据支撑、可被审计带向未来。它明确不声称：backend parity、force-vector parity、contact parity、robot dynamics parity、trajectory parity、task success、官方 benchmark 复现、模型能力、hardware readiness、real-world safety。用记录里的原话："It does not make MuJoCo and Genesis physically equivalent." 把"一致"与"已记账的不一致"分得清清楚楚，本身就是结论——而不是退而求其次。

这一节带走的

三点：（1）judgeable loop 把比较拆成两层——fairness gates（同 state0 hash、同 action schedule、control ack、joint response）先过，physical verdict（matched / mismatched / blocked_with_evidence / not_compared）才被允许；（2）R13 在 7 个 actuator 上逐项验证力律 $\text{force}=\text{gain}\cdot\text{target}+\text{bias}_0+\text{bias}_1 q_{pos}+\text{bias}_2 q_{vel}$，delta 全 0.0；（3）R15 关闭为 closed_with_accounted_non_equivalences、unaccounted_blocking_reasons=[]——把每个未知 blocker 变成已声明的 non-equivalence，parity 依旧不声称。

账记清了，差异有据了。但还有一个更刺人的问题悬在整条线索之上：这一切，到底算不算"faithful reproduction"？下一节，是这本书的良心时刻。
