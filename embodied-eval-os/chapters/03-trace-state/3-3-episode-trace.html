EpisodeTrace 解剖

我们终于爬到脊柱顶端的 L6。这一节不讲愿景，只解剖一个真实的 dataclass：EpisodeTrace。它是 EOS 全部主张的最终落点——「The trace design is the product boundary.」一条 trace 凭什么算强证据而不是一堆数字？答案全写在它的字段里：provenance、privileged-state policy、claim boundary、六大组件。我们逐字段看，并看看为什么少了其中任何一个，这条 trace 就不算证据。

真实的字段表

先把 core/state/trace.py 里的两个 dataclass 完整摆出来。这是代码，不是示意：

src/embodied_eval_os/core/state/trace.py
@dataclass
class EpisodeTrace:
    episode_id: str
    task_id: str
    scenario_pack: str
    backend_profile_id: str
    physics_profile_id: str | None = None
    renderer_profile_id: str | None = None
    seed: int | None = None
    model_profile_id: str | None = None
    versions: dict[str, Any] = field(default_factory=dict)
    backend_components: dict[str, Any] = field(default_factory=dict)
    privileged_state_policy: str = "model_input_excludes_privileged_state"
    claim_boundary: str = (
        "Trace evidence only; no simulator fidelity or real-world safety claim."
    )
    steps: list[TraceStep] = field(default_factory=list)
    episode_metrics: dict[str, Any] = field(default_factory=dict)
    metadata: dict[str, Any] = field(default_factory=dict)

每一步则是一个 TraceStep：

src/embodied_eval_os/core/state/trace.py
@dataclass(init=False)
class TraceStep:
    step_index: int
    time_s: float
    observation: dict[str, Any]
    action: dict[str, Any] | list[float] | None
    physical_state_projection: PhysicalStateProjection | None = None
    task_semantic_state: TaskSemanticState | None = None
    prediction: PredictedFuture | None = None
    metric_results: dict[str, Any] = field(default_factory=dict)
    privileged_state_visible_to_model: bool = False
    metadata: dict[str, Any] = field(default_factory=dict)

注意 TraceStep 怎样把上一节的三层状态收编进来：每一步挂一个 physical_state_projection（L4）、一个 task_semantic_state（L5），可选一个 prediction（给世界模型评测用的 PredictedFuture）。脊柱在这里合龙：逐步的物理与语义证据，被串成一条带时间轴的 episode。下面这个部件让你交互地浏览一条真实 trace 的 JSON，重点看高亮的 claim_boundary 与 privileged 字段：

展开各字段。留意 claim_boundary 与 privileged_state_visible_to_model 怎样把「这证明了什么」直接写进数据里。

versions：没有它，这就不是证据

versions 是整条 trace 里最朴素、也最关键的字段。它装的是这次评测的provenance（出处）：repo commit、scenario pack version、task spec version、backend profile version、asset manifest version、model checkpoint hash、seed、以及 determinism 相关的环境变量。EOS 的措辞毫不含糊：

“Without this metadata, the trace is not considered valid evidence.”

这一句把 versions 从「锦上添花的元数据」提升为「证据资格的前提」。一条没记清自己跑在哪个 commit、哪个资产清单、哪个 checkpoint、哪个 seed 上的 trace，无法被任何人重跑、复核、归因——它只是一堆数字，不是证据。这也是为什么 EpisodeRunner（Path A）会用 git -C <repo_root> 刻意记录所属 repo 的 HEAD，而不是当前工作目录的——它要确保 provenance 指向正确的源头。

从评测科学 看 versions = 每次评测自带的 Model Card + reproducibility checklist

评测科学里有两件成熟的工具：Model Cards（Mitchell et al., FAT* 2019）要求每个模型披露它在什么条件下被评、适用边界在哪；NeurIPS reproducibility checklist（Pineau et al., JMLR 2021）要求论文交代 seed、依赖、环境，好让别人重跑。EOS 的 versions 字段，就是把这两件原本写在论文附录里的东西，下沉成每一条 trace 自带的、机器可读的结构。Henderson et al.（"Deep RL that Matters", AAAI 2018）早就示范过：不记 seed 与环境变异的 RL 结果，复现起来天差地别。EOS 干脆让「不可复现的 trace」在定义上就不算证据。

privileged_state_policy：模型看不到的，才公平

两个相关字段守着「公平性」：trace 级的 privileged_state_policy（默认 "model_input_excludes_privileged_state"）和步级的 privileged_state_visible_to_model（默认 False）。规则是：默认情况下，喂给模型的输入不含 privileged state（比如 evaluator 才该知道的真值、native 求解器内部量）；evaluator 与 recorder 可以看，但模型不行。如果某个 benchmark故意让模型条件于特权状态（state-conditioned eval），它必须把那个步的 privileged_state_visible_to_model 显式置 True——显式标注，不许偷看。

这条策略和 RPF live loop 里的 _build_model_visible_observation() 是一对：后者在喂给 policy 之前主动脱敏（去掉 privileged、native dump、solver diagnostics、evaluator truth），前者把「脱敏了没有」记进 trace 供事后审计。一个在运行时执行，一个在证据里留痕。

claim_boundary：把「不能证明什么」写进默认值

最能体现 EOS 性格的，是 claim_boundary 这个字段有一个默认值：

src/embodied_eval_os/core/state/trace.py
claim_boundary: str = (
    "Trace evidence only; no simulator fidelity or real-world safety claim."
)

换句话说，一条 trace诞生时就默认声明了自己的谦逊：我只是 trace 证据，我不声称仿真器的物理保真度，也不声称真实世界安全性。你得主动去放宽这个边界，而放宽必须有据。这正是 EOS 把「claim boundary」做成签名组件的方式——它不是写在文档里靠人自觉，而是焊进 dataclass 的默认字段，每条 trace 都带着它。这也是本书那些琥珀色 claim 方框的代码源头。

backend_components：六个，永远六个

backend_components 字段装的是 铁律三要求的那六个组件，逐 trace 落盘：

backend_components 的六个键
platform · physics · renderer · sensors · control · process_runtime

这不是装饰。Path A 的 EpisodeRunner 里有一个常量 STANDARD_BACKEND_COMPONENTS = ("platform", "physics", "renderer", "sensors", "control", "process_runtime")，强制把这六个键写进每一条 trace。它的作用是：你永远无法在 trace 里把一个后端含糊地写成「Isaac」或「MuJoCo」——你被迫交代是哪个 platform、哪个 physics、哪个 renderer……于是「换了一个组件」这种跨后端实验，在证据层面就天然可追踪（哪条轴变了，trace 里一目了然）。

State V2 守门：from_dict 会拒绝 legacy key

上一节预告过的牙齿，在这里咬合。TraceStep.from_dict 在反序列化前会先扫一遍 legacy key：

src/embodied_eval_os/core/state/trace.py
LEGACY_TRACE_STEP_KEYS = {
    "canonical_physical_state",
    "task_world_state",
    "world_state",
    "metrics",
}
# ...
legacy_keys = LEGACY_TRACE_STEP_KEYS.intersection(payload)
if legacy_keys:
    raise ValueError(
        "TraceStep payload contains legacy State V1 alias keys; "
        "use tools.migrations.state_v1.load_legacy_trace_step()"
    )

一条 State V1 的 trace 喂进来，不会被悄悄「容忍」或半解析——它会直接抛错，并把你指向 tools.migrations.state_v1。这跟 No Silent Fallback 是同一种性格：宁可显式失败，也绝不静默地把一个含糊的输入当成有效证据。证据脊柱在入口处就立着一道闸。

一条 EpisodeTrace 证明了什么 · 不证明什么

一条字段齐备的 EpisodeTrace证明的是：这次 episode 在可复现的出处下、用公平的可见性规则、记录了逐步的物理与语义证据，并自带它该被怎样解读的边界。它不证明 claim_boundary 默认值里点名的那两件事——仿真器物理保真度、真实世界安全性——除非有额外证据并显式放宽边界。trace 是「证据成立」的必要条件，不是「结论成立」的充分条件：强证据 ≠ 强结论。下一节会从反面把这一点钉死。

这一节带走的

三件事：（1）EpisodeTrace 是脊柱顶端的 L6，TraceStep 把上节的三层状态串成带时间轴的 episode；（2）四个签名字段各司其职——versions（没它就不算证据）、privileged_state_policy（默认不让模型偷看真值）、claim_boundary（默认就谦逊）、backend_components（永远六个，强制写入）；（3）from_dict 会拒绝legacy key——证据脊柱在入口立闸，不静默容错。
